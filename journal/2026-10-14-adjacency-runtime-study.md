Read current doctrine, repository instructions, native runtime/CUDA resource
ownership, pair extension ABI, bindings and build configuration. Revisited the
pinned Wafer/GPU MODE study and its direct prefix-scan reference. Browsed primary
CMU/NVIDIA sources and acquired four original PDFs into ignored papers/pdfs with
SHA256 and restoration URLs. Read scan construction/forward-progress discussion,
CSR and skew-degree gathering, prefix-sum applications, and sorting design.

Saved papers/2026-10-14-adjacency-runtime-study.md, adjacency-runtime.bib and the
PDF acquisition catalog. Recommended a dedicated synchronous ABI5 library,
owned hierarchical integer GPU scan, count/scan/fill plus an actual mate/face
reader, unspecified physical row order with deterministic typed semantics,
bounded high-degree membership, checked extents and call-owned cleanup. Recorded
first-call and warm-runtime scopes and deferred allocation/residency tuning.

Initial advice highlighted sorting if canonical physical row order were promised.
Root clarified that the intended contract explicitly leaves row order unspecified
and asks for a separate flat operation rather than extending Engine. The study
reflects those choices; no sorting stage is required for the proposed reader.
No product execution, native compilation, mutant, dependency adoption or production
source modification occurred. Shared existing source archives and protected
qualification binaries were left intact. Root owns subsequent design integration.
