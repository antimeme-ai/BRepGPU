# NVIDIA polygon export subplan

Research and proposed unit only. The actual unchanged CPU producer attempted
both predeclared policies on the complete original movement. Our triangle-only
exporter rejects three definitions; read-only ring inspection distinguishes six
legitimate rectangular quads in definition 1808 from genuinely crossed
dominant-plane spring/spiral polygon walks. Existing original source, owned
mesher/native binaries and running complete qualification remain unchanged.

Design/source reading and actual geometry diagnostics:
`papers/2026-10-15-om10-nvidia-polygon-export-study.md`.

The useful bounded capability is official SDK triangulation of exact
axis-extruded rectangles along any coordinate axis, preserving their actual vertex identity, XYZ, parent
face ancestry and original per-corner normals. No generic owned polygon
triangulator or SDK-ring repair is selected. Return unsupported for rings that
do not satisfy the official method's preconditions.

Selected implementation sequence, accepted by parent and independent review:

1. Establish a genuine fleet RED using the unchanged actual date-disc producer
   failure and a small literal rectangle at the extraction boundary. The latter
   must check its four original boundary edges, exactly two triangles, opposite
   shared diagonal, original normals/keys and no moved/added vertices; a rotated
   loop, reversed loop and all three coordinate axes attack order assumptions.
   An untouched sibling triangle shares a rectangle vertex with different
   literal normal bytes and user fields; verify its boundary and each parent's
   byte-exact normals/user-field restoration. Crossed/nonrectangular
   inputs must reject rather than be silently fan-triangulated.
2. Factor existing Corner/Triangle/Mesh and extraction into
   `native/om10_nvidia/raw_mesh.hpp/.cpp`, linked by the native producer and
   literal SDK fixture. Preserve existing CLI, main's writer, complete
   per-definition rejection and BGREFM01. The fixture authors SDK polygon input,
   source-face labels and explicit normal values; it tests extraction, not CAD
   source truth. Pin new helper files in the NVIDIA caller only. No owned
   rendering caller/source changes.
3. Snapshot parent polygon/vertex normals and source labels. Check the exact
   rectangle's directed alternating four-edge construction, finite XYZ, four
   distinct physical keys and both nonzero side directions before using public
   SDK ancestry tags and temporarily
   detaching raw-XYZ face labels. Call official `TriangulatePlanar` only.
4. Re-enumerate the final SDK PolyBrep, enforce exact original physical identity,
   parent boundary and two-triangle contracts, recover original parent normals,
   retain a final polygon-pointer→parent map before restoring user fields,
   restore labels/user fields through RAII and write complete meshes. Unknown
   ancestry is a hard error, never inferred. On SDK error/throw/partial mutation,
   restore every valid re-enumerable tagged polygon, reject the whole definition
   and let the existing caller destroy that PolyBrep before any reuse. The
   helper deletes neither mesh nor source Brep. Reject partial/error
   results. Record the official post-tessellation step and counts/timing.
5. Run focused literal/affected existing producer checks and a bounded sanitizer
   check for mutator ownership/lifetime. Independent reviews attack raw-space
   versus UV interpretation, child ancestry, normals and complete extraction.
6. Run only actual 1808 under both unchanged policies with the existing physical
   shell/original Euler mechanism. Preserve the other four actual failure
   definitions explicitly; do not pretend a complete reference model exists.
