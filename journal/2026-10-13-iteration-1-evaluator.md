# 2026-10-13: owned CPU/CUDA evaluator implementation

After the accepted written plan and canonical-header handoff, added a direct native check for the analytic dyadic rational six-jet, full-count SoA worker ranges, invalid-slot NaNs, constant degree-zero derivatives and an empty range. Its first link failed on the missing CPU evaluator, before algorithm implementation; the independent Python qualification lane also recorded its direct red harness.

Implemented `native/evaluator.hpp`, `native/evaluator_cpu.cpp` and `native/cuda_backend.cu` against the runtime-owned headers. CPU uses direct Bernstein basis/derivative sums; CUDA uses bounded scalar-channel tensor de Casteljau with order-specialized execution, explicit nested FP64 FMA and direct quotient divisions. Per-query failures fill every requested field with NaN and preserve canonical statuses.

The private CUDA backend owns context stream, patch/query/result allocations and optional profiling events. It saves/selects/restores thread device state before token publication, completes its owned stream, cleans partial creations, returns cleanup diagnostics and marks documented fatal errors for core-owned process poison. It has no public handle registry or device reset. Profiling events are created only when requested.

The direct native CPU check passed with optimized strict floating-point flags on the local ARM compiler. The local sanitizer process stalled before `main`; a sampled stack showed AddressSanitizer shadow-memory initialization, and that owned process was terminated. It supplies no sanitizer qualification result. This verifies those numerical helper cases, not the supported Linux x86-64 public ABI or a GPU result. The first pinned Linux `sm_60` compile passed: order 0/1/2 use 46/58/72 registers, 64/128/192 bytes of stack and no reported spill loads/stores. Stack usage is not a claim of zero local memory. Replaced bounded diagnostic formatting with explicit terminating character copies after GCC's truncation warnings. Independent corpus qualification, Linux/P100 memory checking and cross-owner review remain required. No new dependency or Git mutation was made by this lane.
