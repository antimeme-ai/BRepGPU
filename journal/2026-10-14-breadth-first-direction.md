# Intentional breadth-first delivery

The operator asked to touch every major topic/theme with a working beachhead
before returning to refine or strengthen established capabilities. Narrow
scope does not relax first-pass correctness. This supersedes treating further
single-patch off-grid bound improvements as the automatic next delivery.

Updated the acceleration roadmap with an explicit selection policy, a theme
table separating first operations from return-pass work, and a dependency
diagram that separates meshing, pair discovery, features and GPU adjacency.
Preserved the delivered numerical evidence and existing architecture; no new
product capability, benchmark or speedup is claimed. Linked the policy from
the README and local issue index.

The next design unit is an immutable owned body snapshot consumed by a
part-level sampling/normal job. A narrow reference adapter, conservative pair
discovery and analytic fixtures for other themes have independent paths. General
import, complete rational intersections, general contact handling and full GPU
Boolean residency must not become hidden prerequisites for narrow operations.

Body frames, trim coverage, shared spatial-edge/UV correspondence and explicit
failure outputs remain substantive requirements. A mesher requires actual
approximation and boundary checks; a sample cloud is a separate output.
Feature, contact and GPU topology beachheads are named explicitly so they are
not indefinitely deferred behind a general curved Boolean implementation.

This delivery edits planning/documentation only. Product design, adversarial
review, implementation and qualification remain required for each operation.

## Review and validation

Independent topology/dependency review accepted the breadth-first coverage
after three findings were fixed: the reference adapter is an optional input
in the diagram; the README no longer places every feature after closed-solid
Boolean work; and required boundary/chart semantics are developed with the
first body consumer rather than deferred until afterward. The reviewer
rechecked the focused changes and reported no remaining blocker.

The feature row explicitly requires constructing the narrow fillet/offset
outputs rather than only preparing fixtures. Delivered numerical capabilities
and proposed beachheads are distinguished. The reviewer confirmed early
curve/trim, contact, arrangement, feature and GPU adjacency work, with CPU/GPU
placement separate from geometry coverage.

Checked all 65 relative link targets across the four changed documents and
Git whitespace checks. The final edits changed no link targets. Inspected
the Mermaid dependency syntax and optional-input relationship. No product
code changed, so no native qualification or performance trials were run.
