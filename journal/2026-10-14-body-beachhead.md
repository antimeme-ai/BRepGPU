# First body-level beachhead

The operator authorized proceeding after selecting intentional breadth-first
delivery. This branch implements one owned immutable body snapshot and its
sampling/normal consumer, with only the boundaries/charts that operation needs.
Constructed box, cylinder and one-hole plate fixtures avoid a general importer
or Boolean engine becoming prerequisites.

Design and source study retained under docs/BODY_SAMPLING_DESIGN.md and
papers/2026-10-14-body-*-study.md. Independent topology/oracle/runtime review
accepted the corrected design. Clarifications establish exact prepared-snapshot
binding, query-row/status versus batch diagnostics, lifted periodic charts,
hole-sensitive Euler and exact submitted-UV trim membership. The plate hole
has no representable dyadic UV boundary point; its symbolic edge map retains
the boundary independently of rounded query classification.

The implementation plan records public interfaces, canonical plane maps,
immutable data ownership, direct oracle tests, unchanged native execution,
actual caller outputs and a small complete-caller timing matrix. Independent
plan reviews accepted the scope. The oracle reviewer retracted an initial
mutable-Patch concern after inspecting the actual tuple-copy implementation;
no redundant geometry wrapper was added.

Body records/classification and normal/scatter execution are explicitly CPU
Python. The existing C++/CUDA evaluator supplies one mixed first-jet batch.
No production dependency, ABI or native math/toolchain change is selected.
The current qualified core/plugin binary hashes were checked on the execution
host before implementation. Product execution/qualification will run there.

Issue15 tracks the operation. Frequent design/test/implementation/result commits
on feat/body-sampling will retain its history; the qualified delivery will be
merged before deeper numerical or meshing work. Native baselines, SDK components
and private operational logs remain outside published artifacts.
