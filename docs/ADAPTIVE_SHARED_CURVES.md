# Cached source curves and shared occurrence traces

The second native adaptive operation takes an original definition to complete
shared physical edge chains and every incident use's bounded chosen trace.
CPU1, CPU4 and both P100s pass the same original-output checks across ten authored
families. See the [results](../results/adaptive-curves-2026-10-16/REPORT.md).
Connected trimmed faces, complete components and the actual watch follow this
operation in the [delivery plan](ADAPTIVE_MESHER_PLAN.md).

## Source and numerical contracts

Original SourceStore values remain authority. Packed curve roots consume original
homogeneous coefficients and true knots, retaining separate original evaluator
and prepared interval roots. Polynomial and positive rational curves support
2D/3D and degree0–32; analytic line/circle/ellipse descriptors retain original
frames and both literal radii. Saved adapter approximations do not replace the
original source. Coordinates and allowances are already millimetres;
source units metadata does not rescale them again.

One DefinitionBoundaryForest owns physical keys, actual XYZ, original endpoint
associations, revisions and all split transactions. Original vertices stay fixed.
Fresh quality queries create fresh forests over retained numerical records;
a coarse query never inherits a previous fine physical chain. Numerical identity
includes source/exact parameter/profile/stage and fixed endpoint words. Use
identity additionally retains original loop/junction, traversal, mapped s and
periodic branch. Equal XYZ never welds source IDs or seam occurrences.

Positive rational actual-chord bounds use original N−W L with positive W, where
L is the SAME emitted endpoint chord. Analytic bounds use original derivative
bounds. Checked monotone line-image maps retain their covector, original scalar
profile and actual chord/trace scalar endpoints; t³ need not split merely because
its speed differs from a straight guide. Paired midpoint restriction emits both
children from one O(p²) convex de Casteljau pyramid. Curve point/restriction
arithmetic uses the same explicit CPU/GPU convex interval DAG.

Original V↔Ce and declared-alias guards run before positional refinement,
including wires. A fixed source mismatch cannot be cured by subdivision. Per-use
original V/Ce↔S(chosenUV) guards remain separate from actual Q rounding and the
whole carrier-trace positional bound. Authoritative boundary-domain displacement
is retained separately and added once to that use's trace allowance. It is not
an interior face-domain homeomorphism or a complete trimmed-face guarantee.

Finite recovery includes exact plane projection and verified guide candidates;
cylinder seam/iso and harmonic identity profiles check their actual source
assumptions. Literal stored double 2π is not an exact symbolic period. Unknown
maps, unsupported inverse/lift/pole profiles, unresolved numerical floors and
resource exhaustion return named failures without partial successful output.

## Execution and output

Build the strict native target `brepgpu-adaptive-curves` using the existing
[Linux Clang18 profile](../tooling/native_cpu_rigor.cmake). CPU-only configuration
requires no CUDA module. Example, using a SourceStore file and its original
DefinitionID:

```sh
brepgpu-adaptive-curves --source part.bgsource --definition 200 \
  --output new-boundary-result --threads 4 --node-source-mm 1e-8 \
  --positional-mm .02 --positional-mm .08 --positional-mm .02
```

For P100 add `--backend p100 --cuda-module LIBRARY --device 0` (or1).
`--memory-mib`, `--max-nodes` and `--max-depth` bound the operation. Original
curve roots, controls, samples and numerical bounds remain resident. Actual
curve evaluations, paired subdivision, physical/trace bounds and stable frontier
mark/scan execute on GPU. Native CPU owns exact identity, source preparation,
selected original carrier guard samples, bounded precise work and publication.
There are no production Python geometry callbacks.

Each query writes BGACRV01 with actual source-edge chains, original aliases,
exact t, XYZ and constructed revisions, every use/site/interval, line/cylinder
map payloads and distinct bounds. Its [wire contract](adaptive-curves-caller-unit.md)
contains no pointers or numerical allocation offsets masquerading as source IDs.
Logical node keys are scoped to the retained artifact/query; cross-quality
comparisons use original edge plus exact t. `queries.tsv` records actual work,
cache reuse, transfers and reservation scopes; `timings.tsv` separates decode,
selection, compilation, device open, construction, output and close. Publication
never replaces an existing directory and removes only its own staging on failure.

## Grounding and checks

The [numerical study](../papers/native-adaptive-curves-geometry.md),
[construction study](../papers/native-adaptive-curves-construction.md) and
[runtime study](../papers/native-adaptive-curves-runtime.md) record exact primary
paper sections, pinned NVIDIA/OCCT functions, assumptions, rejected tradeoffs and
owned improvements. Their finite unit plans and actual-source review reports
precede and accompany implementation. References are studied, not dependencies.

The independent original-output reader forms exact rational residuals against
actual emitted chords, checks full affine plane traces, analytic circles,
original incidence and actual map payloads. Backend parity tests placement
separately. Direct numerical, physical-owner, trace and lifecycle checks,
scoped host/device instrumentation and source reviews address different fault
classes. External community alpha suites and the NVIDIA comparison/backfill
remain required by their existing plans; this is not an alpha qualification.
