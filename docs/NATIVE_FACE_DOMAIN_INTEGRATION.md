# Native sampled-face consumer integration

Proposed bounded connection after the standalone native domain unit passes its
direct correctness, resource, analysis and actual difficult-face performance
checks. The operator authorized beginning the C++ transition and pursuing the
diagnosed fixes. This connection changes the production consumer; the earlier
standalone module alone does not accelerate a watch render.

## Contract

`mesh_imported(..., domain_backend='native')` selects the owned native engine for
sampled boundary simplicity and initial hole/ear triangulation. A named
`domain_backend='python'` remains an explicit legacy reference for same-input
comparisons and diagnosis. Unknown backends and missing native libraries fail
visibly; load the engine and validate its symbols before expensive preparation,
so an invalid library or missing runtime dependency fails there too. There is
no automatic fallback. Existing `_boundary_intersection` and
`_triangulate` implementations remain independent legacy models.

Select the two callables once at the beginning of the operation. Pass the selected
boundary checker into `_coordinate_circle_schedules`, including initial admission
and candidate rechecks. Use the selected checker and triangulator on each final
immutable face domain. Preserve every source node ID, physical edge sample,
coedge occurrence, exact original UV, quality limit and source closure. The new
engine owns its copy for each operation. Repacking between separate calls is
included in the delivered cost; persistent face/session reuse is later work.

Source sampling, canonical edge schedules, carrier evaluation, independent
oracles, refinement and display stay with their existing owners. Exact bridge
distance ordering can change hole diagonals as declared by the module design;
admit complete geometry/source identity using the independent domain/shell
oracles, rather than requiring legacy triangle equality for these cases.

Add the module, exact header, C ABI, wrapper and selected native shared library
to actual watch provenance. Watch source pins include the new C++/wrapper files;
binary pins include the exact library selected through the binding's documented
resolution. Resolve that path to an absolute path before passing it to the
dynamic loader; a relative bare name must not invoke a different search policy
than the file whose bytes were pinned. Recheck these pins after each operation, alongside the existing
adapter/display/plugin pins. Persist the backend choice in the qualification and
render inputs. A Python reference run records its explicit backend instead of
claiming a native execution.

## Plan and relevant evidence

1. Independent review of this design/plan, resolve findings before product edits.
2. Fleet RED on a small existing imported fixture: explicit native/Python backend
   selection and rejection of unknown/missing native engines. Expected failure
   initially is the missing keyword/call routing. Add a direct circle-schedule
   checker routing case only if the existing fixture reaches that stage.
3. Implement only the selected dispatch and provenance paths. Run the new focused
   test and existing imported meshing/geometry/source/assembly consumers with the
   release native library. Native standalone external and sanitizer coverage
   belongs to the preceding unit; repeat only paths affected by new findings.
4. Independent implementation review. Fix all valid findings before actual use.
5. Reproduce one complete original definition, independently qualify source,
   complete mesh, shell and bounded geometry at unchanged watch quality. Compare
   whole-operation native and Python time on the same prepared source and core;
   preserve censored reference outcomes. Separately report capture, domain,
   refinement and qualification costs where available. No saved-face microtime
   becomes a complete-part or whole-watch speedup.
6. Only after the actual face and complete-part checks pass, select a newly pinned
   whole-watch attempt in the isolated checkout. Preserve the old live run until
   its disposition is explicitly chosen. Do not restart the old pinned checkout
   or edit files underneath it. A new whole run may reveal another remaining
   Python bottleneck; report actual progress and diagnose before expanding scope.

This first connection does not migrate the source model, refine algorithm,
independent checker or renderer to C++. It supplies a complete production
consumer for the first native ownership boundary and measurements for choosing
the next one. External alpha qualification and the post-watch NVIDIA README
reference backfill keep their original requirements.
