# Complete native components

`ComponentMesher` owns a bounded pool of native face workers over one fixed
original source bank. Each query selects one complete original definition and
exact positional/node allowances. CPU threads advance face work; an optional
P100 performs the existing actual curve/surface numerical work.

Every face arrives before shared-boundary requests are united and refined.
Unchanged faces retain their exact captured boundary snapshot. The final actual
facets pass the existing physical-key contact horizon before the service returns
an immutable result. Work/resource failures drain tasks and leave the failed
service terminal. Saved host results survive close.

The direct original-source cohort passes twelve queries and thirty-six complete
face outputs across CPU1/CPU4/both P100s: a six-face closed box, a periodic seam
and a square/circle definition that requires real shared-edge refinement.
Captured artifacts match byte-for-byte in this fixed-pool fixture. Distinct-ID
coincident faces refuse without output. Scoped CPU4 memory/concurrency sanitizer
checks also pass. These checks establish this component connection; they do not
establish an imported assembly, singular quotient charts or a GPU speedup.

The [coordinator subplan](adaptive-component-coordinator-unit.md) records API,
literature/reference grounding and execution boundaries. The
[original-output oracle](adaptive-component-oracle-plan.md) describes the finite
source/physical-incidence checks. The [implementation journal](../journal/2026-10-17-adaptive-component-coordinator.md)
records actual outcomes and integration limits. The native component caller and
source-to-display connection continue the same mesher design toward the watch.

The native caller publishes original source bytes, every face, its exact paired
boundary snapshot, and external indices/timings in one new output directory:

```sh
brepgpu-adaptive-component --source original.bgsource --definition ID \
  --output NEW_DIRECTORY --positional-mm .005 --node-source-mm .001 \
  --threads 4 --face-owners 2
```

For P100 add `--backend p100 --cuda-module MODULE --device 0`. Repeated
`--positional-mm` values reuse the fixed source/service bank; each query gets a
fresh physical forest and exact assembly transport. Surface-owner counters are
cumulative; boundary/contact counters describe the current query. Setup/close
and full native costs are separately named. A failed run leaves no final output
and preserves an existing destination. See the
[caller plan](adaptive-component-cli-unit.md) for limits and file semantics.
