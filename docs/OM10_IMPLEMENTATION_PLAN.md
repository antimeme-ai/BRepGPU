# Complete OM10 implementation and actual CPU/P100 graphics

Accepted after all three conceptual owners reviewed both
[the design](OM10_IMPLEMENTATION_DESIGN.md) and this plan. Source-schema findings
on styles, directed edge parameters and nonidentity pcurve maps are incorporated
in the geometry owner's single schema before dependent implementation.
Written lane subplans remain with the studies/journals. Execute
product/native/tests/geometry only on the fleet. Static inspection and publication
run locally. All work remains on feat/om10-whole-assembly with coherent commits.

1. Establish independent red at the concrete new APIs. Oracle owner writes
   source/mesh/assembly/native direct fixtures and checks; native owner may own
   focused native failure/lifetime harnesses. Root writes assembly red if not
   already covered by the independent lane. Run fleet missing-API red honestly,
   then implement each invariant. Do not wait for a complete universal suite
   before starting: enlarge direct cases as actual source families are extracted.
2. Root configures/builds the retained pinned OCCT8.0.1 source headlessly on the
   fleet into ignored quarantine/om10/occt-install. All modules off except required
   TKDESTEP/TKMesh and their dependencies; no Draw/OpenGL/Freetype/Tcl/Tk/optional
   framework dependency. Retain source archive/revision/restoration and build
   recipe. Geometry owner independently owns optional adapter CMake/source;
   root supplies its prefix. OCCT extraction is foreign CPU preparation, measured.
3. Source/mesh owner implements one conceptual invariant: optional native adapter,
   python/brepgpu/imported_source.py and imported_meshing.py. BGSRC001 is exactly
   the study's schema, preserving complete original source IDs and typed model.
   Perform first whole-source extraction early without rendering, inspect actual
   pcurve families/parameter maps, translation correspondence/tolerance changes,
   all source faces/coedge occurrences and units. If the actual source reveals
   a missing geometry family, study it and amend the written local subplan before
   implementing; no unsupported record may be omitted. Then own canonical shared
   edge sampling, periodic domains, multi-hole complete triangulation, conforming
   refinement and immutable provenance-rich mesh plus BGMESH01 writer. Mesh all
   107 definitions; no product OCCT triangulation fallback.
4. Native display owner implements native/om10 standalone CMake/executable and
   explicit optional CUDA plugin. Preserve existing public ABIs/builds. Shared
   tagged carrier first jets, limiting normals, exact alpha0 placement and native
   tile CSR/display form one owned unit. Implement CPU1/useful multicore and CUDA
   sm60 with the accepted binary inputs. Source evaluation-only and projected-only
   modes qualify real source before rendering. Output actual jets/world/snapped
   diagnostics, RGBA/depth/primitive/instance IDs and named synchronized stage
   walls. Retain per-process geometry/storage/workers across view batches so
   reused measurements describe real reuse. Fail explicit on overflow/nonfinite,
   malformed ownership, allocation/device/launch/copy errors; no backend fallback.
5. Root owns assembly/explosion and complete caller in
   python/brepgpu/imported_assembly.py, examples/om10_scene.py and
   examples/render_om10.py (plus a benchmark driver if useful). assemble(source)
   builds immutable Assembly(root_product_id,occurrences,groups); each Occurrence
   has stable 1-based DFS id, full tuple usage path, product/solid ID, original
   name/reference and row-major child-to-world3x4 transform. Reject cycles,
   dangling/ambiguous products and nonrigid/nonfinite transforms. Preserve every
   root-expanded leaf; repeated usage IDs in different paths remain distinct.
   Explosion records contain explicit world offsets, separately authored over
   actual hierarchy/bounds; alpha0 directly returns original assembled values.
   Independent raw STEP composition supplies expected placement. Export complete
   source-linked BOM, original path/transforms, authored aliases/palette/layout.
6. Root caller consumes actual owned source/mesh and native output, computes
   matched source-bound cameras, writes source-indexed native scene/views and
   final PNG geometry plus labeled SVG/timing panels. Use source occurrence IDs
   and actual ID/depth for anchors, complete grouped callouts and BOM/detail
   plates rather than dense unreadable leaders. Standard-library PNG encoding
   and SVG presentation need no new library. Existing static SVG rasterizer may
   compose shareable final PNGs separately; measure/name its scope and location.
   Source attribution applies to derived assets and exact input bytes stay private.
7. Independent oracle owner implements source/mesh/assembly/native qualification,
   with original STEP identities/frames, independent Cox-de Boor/analytic jets,
   actual spatial-edge recovery residuals, positive exact saved-UV full-domain
   boundary chains and physical opposed incidence/cyclic vertex links. Include
   singular quotients, seam multiplicity, disconnected/nonconvex/multi-hole
   fixtures and actual large faces. Tiny independent pixel answers test coverage,
   depth/tie/IDs, winding/instances/supersampling/invalid arithmetic. Check actual
   CPU and both P100 jets/projected output before actual watch rasterization.
   Direct bounded output corruptions may demonstrate important faults; no fresh
   mutation campaign, generic certification engine or tests-for-tests.
8. Fleet green and adversarial code review run per unit as it lands. Root and
   independent owner review source/mesh; geometry/oracle owners review native;
   oracle owner reviews assembly/caller and benchmark boundaries. Resolve every
   valid finding with focused reruns; record incorrect findings in journal.
   Run one affected compatibility set after integration. Existing independent
   reference disagreements/alpha qualification remain explicitly separate.
9. Only after complete source geometry, assembly, CPU/P100 evaluation and native
   renderer direct checks/reviews pass, render the actual OM10 assembled and
   exploded. Inspect full-resolution images and saved source/ID/depth/BOM, fix
   presentation defects and rerun affected outputs. Produce assembled oblique,
   exploded labeled and useful detail/top plates at matched quality/cameras.
   All166 occurrences remain modeled in every full scene, including hidden parts.
10. Run benchmarks quietly, separate from builds/tests. Repeat alternating CPU1,
    useful native multicore, P1000 and P1001 runs with unchanged complete source,
    quality and views. Cold wall directly encloses STEP extraction, owned meshing,
    scene/native setup/evaluation/display/download/close, encoding and SVG labels;
    repeated whole walls are actual repeated calls, not sums of stage medians.
    Reused view batches retain actual geometry symmetrically; report their separate
    scope. Record median/range and every requested stage, including shared CPU
    preparation. Never select a winning repeat or imply GPU solid construction.
11. Embed honest actual times/scope/counts/source attribution in graphics, publish
    recipes/reports/BOM/source mapping and README images, update issue60 and journal,
    push substantive commits and merge preserving history. Retain feature branch,
    clean temporary working trees and sync fleet/main. Stop after the complete
    deliverable and relevant checks; alpha is not being cut by this work.

Actual source translation or measured output may require design corrections.
Study the concrete discrepancy, update the relevant design/subplan and review it,
then implement and test. Do not replace the whole-movement goal with a fixture,
silently relax an error criterion or start an unrelated architecture rewrite.
