# Deliver the pierced-feature chain and actual watch study

Design reviews accepted WATCH_CHAIN_DESIGN. This is one actual operation-composition
unit plus its independently owned qualification and real visual consumer. Product,
tests and scene/render execute only on the fleet. No dependency/native build.

1. Independent oracle owner writes feature_bore_oracles.py,
   feature_bore_meshing_oracles.py and test_feature_bore.py /
   test_feature_bore_meshing.py. Source expectations come from actual original
   profile/height/cutter expressions and actual source/control values, not product
   private constructors/map readers. Genuine missing-API fleet red precedes product.
   Check strict whole-circle admission, all source/control/bothUV/trims/material,
   closed entity topology and precise immediate/composed ancestry (all six kinds).
   Mesh truth checks whole exact/rounded positive domain chains and source corners,
   shared physical incidence/vertex links, bound/embedding and failure preservation.
   Include off-center/nonaxis, source-count/frame/height/budget boundaries, tangent/
   exterior/short-cutter negatives, bridge duplicate/alignment cases and a few actual
   output corruptions. No mutation/certification campaign.
2. Geometry owner implements the complete conceptual invariant in feature_bore.py
   and feature_bore_meshing.py, plus lazy BoreResult.tessellate. Preserve actual
   original feature/cutter and all retained carrier bits/Frames. Immediate history
   reuses existing Origin/History/HistoryRecord; composed HistoryPath(root,steps)
   preserves actual cut and extrusion origin objects, with complete root records.
   Actual append ordering is documented in the continuing geometry study and
   coordinated with oracle owner before implementation. Dedicated local curve/UV
   readers support center explicitly; canonical readers/guards stay unchanged.
   The exact one-hole cap bridge/ear algorithm must complete its admitted family;
   fix encountered real degeneracy rather than omit geometry. Publish immutable
   candidates only after supported-domain/topology/history validation. Root reviews.
3. After red/acceptedplan, visual owner implements actual watch scene, indexed CPU
   depth display and source-rich example caller (own examples/watch_scene.py,
   examples/watch_display.py and examples/render_watch.py, or equivalent agreed
   names). Each component is an actual qualified extrusion or bored-result mesh,
   with instance-aware source IDs if reusing part templates. Separate tooth-like
   lugs remain separate modeled components. Keep actual source scales/heights,
   no artificial anisotropic compression or simulated functional claim. Preserve
   component recipes/material/camera/light/inventory and export actual scene PLY,
   per-unique-part source/mesh/history tables. Include oblique hero and exploded/
   close view if useful, keeping truthful captions. NCSX files stay unchanged.
4. Run direct fleet green. Independent source/code/qualifier review resolves real
   findings. Run one affected CPU compatibility set (existing extrusion/meshing/
   cut + new operation), not all historical numerical/GPU tests. Tests/fault
   work and performance never overlap. No measured-source mutation during caller.
5. Run one actual watch assembly/caller, independently qualify every distinct
   constructed part and actual per-instance transformation; follow original/root
   ancestry inside useful consumption. Record construction/mesh/indexed/history,
   independent checks, CPU rendering and export separately and directly enclose
   full caller wall. No GPU Boolean/rendering or performance speedup claim.
   Actual output source hashes must match the final code. Inspect both saved
   geometry/history and actual rendered image. Fix actual defects, rerun only
   affected execution. Three bounded scalar chain cases/repeats may be used only
   if needed for a useful operation-cost comparison; the watch itself is primary.
6. Publish real graphics/PLY/recipes/source-history/report and update target notes,
   README, API/roadmap/issue/journal. Keep owned exact source/correctness first;
   explicitly state schematic/nonfunctional and external alpha limitations.
   Coherent feature commits/PR merge preserve source history and branch; sync clean
   fleet/main and record handoff. Stop after direct obligations/caller/review pass.

Do not let the appearance force unsupported nonconvex/overlapping-cut geometry
into the admitted kernel family. Supported separate solids with explicit assembly
roles are useful. Full functional watch design, involute gearing, escapement,
springs, multiple cuts, general Booleans, native/Python migration and NCSX source
assembly are separate later units. The operator's notes request is maintained in
WATCH_TARGET and the continuing journal, not a second certification artifact.
