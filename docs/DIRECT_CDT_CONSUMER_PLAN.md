# Direct CDT imported-mesh consumer

Proposed bounded connection after actual direct-constructor correctness,
resource/analysis checks and independent general-family performance qualify the
new path. Root review precedes product edits. No running watch file is changed.

`mesh_imported(..., domain_backend='direct')` selects the new direct constructor
for each immutable final sampled face. Existing explicit `native` selects native
ear construction with its conditional Python Lawson improvement, and `python`
retains the Python baseline. The current default remains `native` until actual
complete-part evidence justifies a separate default decision. Unknown choices
and unavailable binaries fail before expensive source preparation; no fallback.

At operation entry, load and check the real direct library ABI/symbols and the
existing native boundary-checker library through their selected absolute paths.
Add a small public availability helper for the direct library, following the
existing face-domain helper. Circle-schedule coordination still needs native
boundary intersections before final face construction; pass that same selected
checker through its current initial and candidate paths. Direct construction's
own exact complete-domain validation replaces redundant final per-face boundary
and hole-winding checks in this selected branch; source-schedule decisions still
perform their existing admission checks.

At the current final `triangulate(node_loops, points)` site, call
`constrained_delaunay(node_loops, points, metric=metric_cache[carrier.id], seed=0)`
for the explicit direct branch. Pass the existing metric exactly, retain all
original node IDs/UVs/physical keys and boundary pairs, and let the constructor
own a copied immutable input. Do not call `_improve_connectivity` afterward:
the direct result already satisfies the selected fixed-site CDT contract.
The conditional surface-error evaluation used only to decide whether to run
Lawson belongs to the old branches. The following real refinement loop and all
its original carrier/curve quality bounds remain active for direct output.

This changes initial connectivity, not source sampling, tolerances, canonical
edge schedules, coedge/chart closures, original source maps, carrier evaluation
or refinement policy. New legal diagonals can change refinement work and final
triangle count; complete source/physical/domain quality establishes correctness,
not equality with the old triangle list. Resource exhaustion propagates visibly
without a partial mesh or a hidden rerun through another constructor.

## Focused implementation sequence

1. Root review accepts this connection only after standalone direct output and
   performance merit actual use. Author genuine missing-dispatch fleet RED in
   `tests/test_native_face_domain_integration.py`, using existing complete
   independently authored `pierced_prism_source` and actual `qualify_mesh`.
2. Extend explicit dispatch and early availability only. On the two-hole solid,
   all three selected backends must independently qualify complete source faces,
   boundary maps and closed physical shells at unchanged quality. Add a wrapped
   actual direct call assertion and a forbidden old-Lawson assertion on the
   selected path; the actual geometric qualifier is the answer oracle.
3. Use the existing tangent-circle sheet fixture to ensure direct selection
   retains real circle-schedule boundary checking and exactly one direct final
   constructor call. Use existing spline-column/cone/plane/source fixtures and
   affected imported-meshing methods for the changed branch. Do not add a new
   general CAD fixture framework or repeat unrelated GPU qualification.
4. Check missing direct library and missing boundary checker before source
   preparation starts; check unknown backend. A direct resource error must stay
   visible. Independent review attacks exact metric dispatch, no fallback,
   source identity, branch-specific bypasses and real refinement quality.
5. Extend render/qualification/benchmark CLI backend choices and source/binary
   provenance. `examples/render_om10.py::pin_files` includes owned direct source
   and headers; direct mode pins both selected native libraries. Add matching
   binary roles and backend/seed values in `scripts/qualify_om10.py` and
   `scripts/benchmark_om10.py`. Recheck pins after operations, using each loader's
   actual resolved file. Keep public reports free of private source paths.
6. Run one fresh actual complete original part with direct selection and
   unchanged watch quality in the isolated checkout. Qualify original geometry,
   full mesh/source maps and physical shell; report preparation, meshing and
   independent qualification separately. Compare the same prepared source/core
   to explicit old native selection, retaining the old censored outcome. No
   saved-face microbenchmark becomes a complete-part/watch speedup claim.
7. Only after that succeeds choose a newly pinned whole-watch attempt. Preserve
   the old live run until root explicitly chooses its disposition. If another
   stage dominates or source input fails, report and diagnose that operation;
   do not relax quality, omit original parts or alter source samples.

The constructor currently admits protected boundary sites only. Refinement can
add interior sites after initial construction using its existing conforming
split logic. It does not route those refined sites back into the narrow direct
API or claim the final refined mesh remains a CDT. The eventual whole-mesh
oracle still checks the actual final domain/source bounds and physical shell.
