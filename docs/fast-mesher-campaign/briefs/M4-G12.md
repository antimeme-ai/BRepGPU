# M4-G12 brief: Invalidation and equivalence under edits

Read with `M4-common.md`. Stub: `papers/2026-10-17-geometry-lifecycle-map.md` §4.1 G12. Bead: `brepgpu-12s.13`.

**Purpose.** Define what change description the mesher consumes from its host,
the invalidation set (changed faces, refined-edge neighbours, halo), the reuse
acceptance (geometry and boundary digests, not deflection), and the
incremental-versus-fresh equivalence the oracle tests. This serves the roadmap:
animation, physics, the complication, and sharpen-in-place.

**Decision it blocks.** M5 §7 and §11.

**Operator decisions that bind this lane.** D-provisional (display only);
D-determinism; G7's paper, `papers/2026-10-17-determinism-cache-keys.md`, which
this lane reads first.

**Questions.**
1. The change description: what the host must say (OCCT
   `BRepTools_History`-style modified, generated and deleted sets) and what the
   mesher derives itself.
2. The invalidation set and its halo, given G2's face-to-edge feedback.
3. Reuse acceptance: the digests and their composition with G7's cache key.
4. Equivalence: what "incremental equals fresh" means under functional
   identity, and its oracle.
5. Literature: Sypkens Smit 2011, Sheffer–Üngör 2001, Parasolid incremental
   faceting, Wu–Sarma 2004 (unread so far), OCCT `BRepMesh_ModelPreProcessor`.

**Measurement.** None.

**Output slug.** `edit-invalidation`: `papers/2026-10-17-edit-invalidation.md` and its sources TSV.

**Done when.** An invalidation rule, a reuse rule, an equivalence statement and
its oracle. Every question has an evidence-backed answer or an explicit "the
literature does not say" with the measurement that would settle it.

**Return.** The four rules. Then the common return items.
