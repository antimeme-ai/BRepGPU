# M4-G14 brief: Sizing beyond the chord rule

Read with `M4-common.md`. Stub: `papers/2026-10-17-geometry-lifecycle-map.md` §4.1 G14. Bead: `brepgpu-12s.15`.

**Purpose.** Decide maximum edge length, grading between a fine face and its
coarse neighbours, and proximity sizing, and whether any of them is needed when
only ε is promised.

**Decision it blocks.** M5 §6.1, and support for analysis consumers.

**Operator decisions that bind this lane.** D-consumers (PrusaSlicer, Cura, one
glTF renderer, fTetWild as the analysis stand-in; PhysX with physics);
D-features.

**Questions.**
1. What each named consumer needs from triangle sizes and shapes: slivers and
   needles in slicers, fTetWild's input tolerance and envelope, and renderer
   interpolation.
2. Netgen `Analyse`, Gmsh size fields and Parasolid local tolerances: what they
   add beyond chord error, and why.
3. Grading at the boundary between a fine and a coarse face, and how it
   interacts with shared edge sampling and growth clusters.
4. Cost: what each sizing term adds to triangle count and time.

**Measurement.** None.

**Output slug.** `sizing-beyond-chord`: `papers/2026-10-17-sizing-beyond-chord.md` and its sources TSV.

**Done when.** A sizing statement per consumer profile. Every question has an
evidence-backed answer or an explicit "the literature does not say" with the
measurement that would settle it.

**Return.** The sizing statement per consumer. Then the common return items.
