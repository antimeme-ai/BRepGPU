# Resident adaptive device unit: scoped algorithm plan review

Reviewed `docs/adaptive-device-unit.md`, actual `cuda/adaptive_api.h`, shared
`adaptive_geometry_types.h` and the native cache caller seam. The selected
resident pools, one outstanding ticket, canonical scan/compaction and shared
numeric operations fit the accepted adaptive primary. Warp-strided rational
nets avoid copying a full degree-bucket net into every thread. Native exact
root/path identity remains outside the device staging ABI. Actual facet bounds
remain necessary after the packet builder; cached four-corner acceptance alone
is not final geometry.

One concrete launch-admission requirement was sent to root: restriction jobs in
one operation must read already-resident prior-operation nets; their complete
destination ranges must be mutually disjoint and disjoint from every parent
read range. A within-batch parent→child dependency needs a subsequent ticket.
Sample destinations and node slots must likewise be unique per operation.
Index/product capacity checks alone do not prevent these write/read races.
Checks belong before launches/resident mutation, under the same bounded staging
owner. With this explicit transaction invariant, scoped plan ACCEPT.

This review does not claim a device build or numerical GREEN. Actual module
source, retryable close and CPU/P100 source-to-triangle reader execution remain
the implementation closure. No second evaluator or additional test campaign
was introduced by this review.
