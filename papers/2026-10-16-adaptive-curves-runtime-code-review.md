# Shared-curve runtime: actual-source review

2026-10-16. Scoped ACCEPT of `native/mesher/adaptive_curves.cpp`,
`adaptive_curves.hpp` and `adaptive_curves_types.hpp` as read after physical exact
certificate flags and canonical increasing image-parameter changes. This is an
independent source review, not another geometry execution or a claim about full
trimmed-face construction.

The physical horizon first folds every interval failure and point promotion.
Only then does the forest receive one union of original interval requests and
expected-key/revision guarded promotions. Every incident face reaches that
horizon before source mutation. Numerical children are reserved before the
forest transaction; existing ready children do not get overwritten while a
worker reads them. Descending original edge ranges reverse physical child
routing while source numerical intervals remain increasing.

Cached point identity includes exact original curve parameter and fixed original
vertex bits where applicable. Constructed sample revisions remain separate from
logical physical keys. Bound tiers include both endpoint cache identities and
precision stages. Fresh queries reset selected stages to BASE without deleting
higher cached tiers. Source and exact-table leases remain immutable.

Trace reuse requires the retained boundary generation to match the current
forest face generation. Freeze remaps all retained use sites through the new
physical snapshot using the original edge and use traversal, rather than
retaining obsolete snapshot indices. It copies every exact reference in physical
bounds, site rows, authoritative components, geometric-line maps and finite
cylinder maps into the new table. Table namespaces reserve all five trace stage
ordinals without sharing a mutable builder.

CPU numerical jobs own disjoint result ranges and their own JobContext budgets;
source/cache inputs are immutable until the complete batch folds. The staged
trace completion route checks the captured identity and work table. Resource or
numerical failure stops the operation instead of publishing a partial snapshot.
Device allocation/ticket destruction is a separate root-owned review scope.

No blocking finding remains in this scope. Product correctness is exercised by
the existing direct source/trace and whole-operation original-output readers;
this review did not add another checker or execution campaign.
