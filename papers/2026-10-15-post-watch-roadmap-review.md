# Independent critique of the post-watch breadth proposal

Read-only roadmap review of [the existing second-pass proposal](../docs/POST_BREADTH_ROADMAP.md),
[deferred work and observations](../docs/RETURN_PASS.md),
[topology architecture](../docs/TOPOLOGY.md), and
[the alpha contract](../docs/ALPHA_QUALIFICATION.md). This proposes sequencing and
completion claims; it selects no implementation, dependency, release scope or
new watch prerequisite. No execution or benchmark was performed.

The proposed direction is sound: finish the watch, discharge the operator's
README-wide NVIDIA CPU reference obligation, then deliver one bounded advance
per major theme before deepening any one. The old roadmap's first result mesh
and extrusion/bore chain are already delivered; repeating those as future work
would obscure the next actual gap.

| Theme | Useful first delivery | Dependency trap to avoid |
| --- | --- | --- |
| Required README references | Map every advertised scenario at a named README revision to actual comparable NVIDIA CPU outcomes, including unsupported/failure dispositions | Do not turn an unsupported counterpart into an obligation to implement a whole new NVIDIA operation, or substitute a successful subset. This is benchmarking, separate from community alpha qualification |
| Mesher scalability | Improve one measured costly source-to-mesh stage on selected actual watch faces and the complete caller, keeping the same source and error obligations | Current read-only opportunity lists are hypotheses. Measure useful stage walls/work first; fewer triangles alone is neither faster output nor unchanged geometric quality |
| Runtime and Python role | Compare one real fresh/reused workflow with explicit native ownership/bulk consumption and CPU/P100 costs, then select a bounded language/runtime decision | A native rewrite can change algorithm, layout and reuse simultaneously. Attribute gains; do not equate faster boxing or isolated CUDA kernels with a shipping-language decision. Do not require a general edit graph or service framework before a retained workflow |
| Revisioned imported-part edit | One user-visible geometry edit on a specifically admitted imported part, producing a separate candidate/result and inspectable unchanged/generated/removed history | A rigid view/instance change is not a part geometry edit. Conversely, the first edit need not support the whole watch, arbitrary persistent naming or a general feature graph. Original source identity, UV correspondence and any approximation provenance must survive |
| Wider SSI/trim/Boolean geometry | Choose the smallest new intersection/arrangement/material capability genuinely required by that edit, then consume its complete result | Selecting a general SSI engine first invites depth-first infrastructure. Pick the edit and its admitted family before selecting this geometry unit; retain unresolved branches/tangencies as explicit failure rather than silently broadening type checks |
| GPU topology construction | Move one established construction step beyond the delivered CSR build/read, consuming the same CPU-defined candidate semantics | Count/scan/fill already constructs adjacency; relabeling it as new construction adds no value. First establish edit identity/publication semantics on CPU, then target one real costly grouping/compaction/assembly step. Slots are not stable IDs; retained results need body/revision/owner checks |
| Actual community replay | Execute a preselected relevant upstream case family through actual BRepGPU operation/result adapters, with original checks and all non-pass outcomes visible | Do not wait for every wider geometry family, or publish another inventory as replay. Existing admitted operations can be challenged now. Passing this beachhead does not satisfy the complete alpha corpus |

Two distinctions should stay explicit across these lanes. First, an import-derived
source is an immutable geometric input with recorded reconstruction/approximation
provenance; a later edit cannot erase that provenance or silently grant a fresh
unbudgeted approximation. Second, application reuse and independent qualification
serve different costs: report useful production work, complete fresh caller and
independent checking separately, preserving any explicitly named qualified wall.

The dependency spine is short: completed watch measurements inform performance
selection; the required README reference map comes next; a concrete imported edit
selects the wider geometry prerequisite; CPU candidate/history semantics precede
moving that construction step to GPU. Runtime work and community replay can use
already delivered operations without waiting for the edit. One beachhead in each
lane is the breadth checkpoint, not completion of every recorded optimization.

Keep NCSX as a sourced follow-up: choose one real component and its geometry/error
contract rather than promising the complete engineering assembly or treating the
existing illustrative fitted scene as owned engineering geometry. No general
sweep/importer prerequisite should be inferred before component selection.

Documentation also needs a small status reconciliation when the roadmap is
updated: the old alpha-gap paragraph says no usable OCCT headers/build were found,
while the current watch work has an isolated source/reference bridge. A usable
reference build is still not a community replay adapter or a corpus PASS. Preserve
that distinction and the operator's unchanged all-required-cases-green alpha gate.
The current watch and reference failures must remain visible until actual
completion; this roadmap does not add new work before trophy delivery.

## Final draft review

Reviewed the actual `docs/POST_WATCH_ROADMAP.md` proposal and the alpha document's
availability correction. ACCEPT. It keeps watch completion active, places the
operator's complete README scenario/reference accounting next, and proposes one
bounded advance in each lane without selecting code or a language migration.
Unsupported NVIDIA outcomes remain reportable outcomes rather than successful
ratios or an obligation to implement missing vendor operations. Community replay
is independent, preserves the complete relevant inventory and changes no alpha
gate. Runtime and source study do not wait for a general solver/edit graph.

One wording finding was fixed: the delivered CPU extrusion/bore/mesh chain is now
explicitly separate from GPU consumers elsewhere. The topology section now
establishes CPU result candidate/history semantics as the model oracle before
GPU construction; actual source/UV/history ownership and failed-publication
semantics remain required. The alpha text accurately distinguishes usable
isolated source/NVIDIA adapters from absent community replay/DRAW/CGAL answers.
No new watch blocker or certification campaign is introduced. This is roadmap
acceptance, not implementation selection or a promise of performance.
