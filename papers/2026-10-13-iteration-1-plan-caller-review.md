# Iteration-one plan: independent caller/oracle review

2026-10-13. Reviewed `docs/ITERATION_1_PLAN.md` against the accepted iteration-one design and topology/roadmap review. Own scope: exact numerical expectations, Python/native caller contract, source/query identity, failure assertions and material task output. No product code was written during this review.

**Disposition: no blocking finding; ready to implement after the plan is accepted and the runtime owner publishes the canonical interface.**

The plan retains a whole useful unit: immutable uploaded patches and queries, independently checked positions/derivatives, a batch caller and an actual carrier-sampling artifact. It does not advertise Boolean acceleration or assume an optional CAD extraction experiment succeeded. All sixteen degree pairs and each order have exact-input checks; order two retains the stricter position/first-derivative grades. The rational circle/cylinder fixture uses exact rational homogeneous controls, avoiding an analytic oracle that silently treats rounded square-root weights as exact conic geometry.

The exact `Fraction` calculations use the represented binary64 inputs, rather than author-intent numbers or a double-precision copy of the device recurrence. Analytic polynomial, cylinder, dyadic bilinear and singular-chart cases attack axis ordering, quotient terms and missing derivative factors independently. Metamorphic cases stay in scope or expect explicit rejection. The harness will record grade maxima and actual offending controls/queries/results, not declare qualification from CPU/GPU parity or averaged error.

Snapshot and runtime requirements are materially testable. The same-sized-different-patch-set case attacks dense-slot reinterpretation. Mutating caller arrays after creation attacks borrowed input retention. Closing patch/query handles while results remain live attacks dependency lifetime. A later evaluation must not overwrite a retained earlier result, and altering a downloaded Python array must not alter resident storage. Mixed valid/invalid queries must retain order, explicit status and NaN in every failed request field. Allocated aligned/misaligned/short/versioned buffers permit hostile ABI tests without forged pointers.

Two implementation prerequisites should be made concrete before consumer coding:

1. **Canonical caller shape.** Runtime owner must publish `Patch`/`Lineage` constructors, library-selection path/environment, `Engine` arguments, `JetBatch.vector` term/index order, status/global-error enum spellings, diagnostics, raw ABI declarations/handle access, and the conversion method signature. The plan correctly assigns one canonical header owner; consumers must not create competing layouts. Result lineage needs an unambiguous association with the bound patch set and source/query metadata, including full body/kind/entity/revision/chart where present.
2. **Declaration before the direct red invocation.** The sequence says red invocation precedes the header/CPU whole unit, while exact ABI spelling is settled in the header. Publish declarations/layout and the caller's loading contract before invoking the red caller so its expected failure is an absent native evaluator/library, rather than an incidental missing Python package or invented signature. This does not require implementing numerical behavior before the red oracle.

Backend fault tests are appropriately separate from geometry qualification. Supported positive-weight patches cannot naturally trigger an invalid denominator or illegal device address; direct invalid-input tests should not pretend to cover fatal execution. The runtime lane owns deterministic test-build-only injection at actual allocation/copy/completion/admission boundaries. Fresh-process fatal-state tests must verify unusable CUDA results and no subsequent success publication, while actual GPU arithmetic/memory checks run on both P100s. No test quota, duplicate certification harness or required mutation percentage is introduced.

Measurements have a useful consumer and correct boundaries. Resident public evaluation includes new-result allocation/checks/synchronization/publication; downloads and cleanup are separate. Host-to-host results include packing/upload/evaluation/download/required checks. Every timed family needs direct truth; the exact corpus can remain small while large performance families use independently derivable analytic outputs. A full-jet throughput result is not substituted for a position-only task, and a device event is not relabeled as public operation latency.

The qualification script must fail if its explicitly requested CUDA backend/device cannot execute. A CPU-only developer run can select CPU intentionally; it must not turn the required both-device qualification into silent skips. Reports should expose successful request count, rejected request count, maximum component error by grade and retained witnesses, while omitting private hostnames and absolute operational paths.

No remaining issue requires expanding iteration one into general knot extraction, trimmed tessellation, inverse-query optimization or topology mutation. Those remain later reviewed units under the roadmap. Header agreement and direct test execution are the next concrete steps.
