# Pair discovery plan: runtime/CUDA/wrapper review

2026-10-14. Accepted; no blocking finding. Reviewed
[PAIR_DISCOVERY_PLAN.md](../docs/PAIR_DISCOVERY_PLAN.md) against the accepted
design and current registry, plugin callback and Python ownership paths.
No product code or execution before the coordinator's genuine fleet red.

The native lane owns the entire ABI4/header/shared predicate/runtime/plugin/
wrapper/callback-fault unit. Two resource kinds, retained indexes and context,
single-context admission, publish_owned and the six-callback optional v4 table
cover the lifecycle without a second registry or device framework. Actual index
download remains mandatory. CPU word ranges and CUDA grid-stride word ownership
share exact bit ordering; empty inputs avoid launch/division. Public record
sizes and private table size are independently admitted by static assertions
and Python ABI checks. Existing layouts/math stay unchanged.

The proposed fault checks address new behavior rather than repeating numerical
truth: optional-table refusal/identity/transient/fatal paths; unpublished-token
cleanup; upload/restoration/copy failure; retained parents; alias/extents and
admission-close races. Cross-family fatal tests check the existing common poison
boundary in both directions while CPU remains usable. Existing injection seams
and sanitizer builds are sufficient; no new fault framework is required.

The oracle lane independently checks actual boxes and every returned bit,
padding/flags/cursors; body exact enclosure stays separate. Scene consumers
copy downloads to immutable values before publication, close children safely
through BaseException, and retain exact source scenes. Agreed primitive handoff:
create_pair_index accepts bounded six-value records; PairIndex.download owns
six-value tuples; PairPage.download owns info with native field names and words.
The adapter freezes those values; native wrapper buffers need not imitate a
new immutable-storage framework.

The backward-compatibility clause should concretely exercise new adapter with
actual old core, new core with actual old plugin, and actual old adapter with
new libraries. Existing evaluation must work; unavailable pairs return explicit
unsupported; a pair refusal must leave old operations usable. These are focused
preserved-binary checks, not another full exact numerical campaign.

The qualification sequence fits the changed source: CPU1/CPU24, both P100
direct suites under Compute Sanitizer, targeted native faults/host sanitizers,
existing geometry suites on new libraries, then small direct production mutants,
actual caller and serialized timing. Private new build paths preserve previous
artifacts. No local product execution or performance overlap is authorized.

Measurements distinguish CPU body/root/world setup and index upload from
retained-page native work, download/cleanup, host survivor decoding and external
caller wall. Optional events are separate from the primary wall matrix; export
is absent from benchmarks. Five-call descriptive ranges and actual upload/mask
payloads support only the named all-pairs operation. No independent-median sum,
clock confidence, intersection or topology-speedup claim follows.
