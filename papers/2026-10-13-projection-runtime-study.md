# Seeded projection: runtime, ABI and residency study

2026-10-13. Research/design proposal for iteration 2; no projection product implementation or dependency adoption is authorized by this report. Numerical convergence and qualification contracts are separate reviewed units. The report studies the current owned core/plugin/ctypes implementation and the pinned primary reference sources already catalogued in `papers/acceleration-roadmap-sources.tsv`.

## Recommendation

Add an owned synchronous batch operation that refines one local target/seed against one existing rational patch per request. Keep every `bg1_*` symbol, structure layout, evaluator query/result meaning, existing status value and private v1 factory unchanged. Introduce distinct projection query/result kinds in the same registry and an optional, lazily negotiated private v2 projection extension. Reuse the v1-created context, stream and patch tokens only after explicit table identity checks.

One immutable request consists of patch slot, local Cartesian target XYZ and normalized seed `(s,t)`. One result row describes a seeded candidate and its convergence outcome. Do not call it a globally nearest point, a complete set of extrema, a trimmed-face projection or an accelerated topology operation. A caller can submit several rows for the same target and different seeds; rows remain independent and ordered. Grouping, deduplication, global selection, seam correspondence and face classification belong to a later consumer.

## What the references actually expose

OCCT separates its broader surface projector from a seeded local locator. `GeomAPI_ProjectPointOnSurf` exposes multiple computed orthogonal projections, their UVs/distances and the nearest computed projection. `Extrema_GenLocateExtPS::Perform` explicitly accepts an initial UV pair and selects either normal-projection or distance criteria. Its implementation follows distinct root-solving and minimization paths with fallbacks. These interfaces support separating the mathematical operation, candidate list and selected answer; they do not justify labeling our single-seed result globally complete. [OCCT surface projector](https://github.com/Open-Cascade-SAS/OCCT/blob/b8f597c677811d1f9f4d8a97f5ae2825c0353a42/src/ModelingAlgorithms/TKGeomAlgo/GeomAPI/GeomAPI_ProjectPointOnSurf.hxx), [seeded locator](https://github.com/Open-Cascade-SAS/OCCT/blob/b8f597c677811d1f9f4d8a97f5ae2825c0353a42/src/ModelingData/TKGeomBase/Extrema/Extrema_GenLocateExtPS.hxx), [implementation](https://github.com/Open-Cascade-SAS/OCCT/blob/b8f597c677811d1f9f4d8a97f5ae2825c0353a42/src/ModelingData/TKGeomBase/Extrema/Extrema_GenLocateExtPS.cxx).

The pinned NVIDIA USD BRep binding presents `surface_closest_point(surface, point)` as a globally closest carrier point with solver-reported natural/NURBS UV representations. Its own documentation excludes a guarantee of discovering every tied spatial minimum or every preimage. The face method instead queries a trimmed face. These are useful comparison outputs with different scopes; neither supplies a replacement evaluator callback, a resident batch API or this operation's seeded-input contract. Reference runtime success/parity is not an independent truth oracle. [Binding](https://github.com/NVIDIA-Omniverse/usd-brep/blob/c9c5979f04cea8c38213004d4f04df0dcfb40d05/source/SmPyLib/src/SmPyQueries.cpp), [C query contracts](https://github.com/NVIDIA-Omniverse/usd-brep/blob/c9c5979f04cea8c38213004d4f04df0dcfb40d05/source/SM_API/inc/SmApiQueries.h), [face binding](https://github.com/NVIDIA-Omniverse/usd-brep/blob/c9c5979f04cea8c38213004d4f04df0dcfb40d05/source/SmPyLib/src/SmPyTypes.cpp).

The C++ SMLib carrier can export degree, natural domain, knot data, Euclidean controls/weights or homogeneous controls. Its raw control ordering is U-major, V-minor. The USD writer emits orders, expanded knots, Euclidean vertices and separate weights in that ordering. Existing source-chart and world-frame handling must therefore remain explicit: preserve the patch's original rectangle and lineage, derive homogeneous local controls deliberately, and transform world targets into the same local frame. Export time, normalization and unsupported extraction are consumer costs rather than hidden projection-kernel work. An exported NURBS surface is not automatically a supported single-span patch. [Carrier access](https://github.com/NVIDIA-Omniverse/usd-brep/blob/c9c5979f04cea8c38213004d4f04df0dcfb40d05/source/SMLib/inc/SmBSplineSurface.h), [USD writer](https://github.com/NVIDIA-Omniverse/usd-brep/blob/c9c5979f04cea8c38213004d4f04df0dcfb40d05/source/BREP_SM_USD/src/SmuConvert.cpp). The extraction limits remain those in the [acceleration roadmap study](2026-10-13-acceleration-roadmap-study.md).

## Native public extension proposal

Use a separate public extension version, provisionally `BG_PROJECTION_ABI_VERSION = 2`, for new descriptors and symbols. Shared handles, `bg_status` and diagnostics remain the existing ABI-1 types; a projection diagnostic still has `abi_version=1`, `struct_size=288`. Do not increment `BG_ABI_VERSION` or change `bg1_abi_info`: existing callers initialize those descriptors to 1.

| New operation | Proposed signature and behavior |
| --- | --- |
| `bg2_projection_abi_info` | New versioned output describes projection options/info sizes, seven output floating fields and widths. Existing `bg1_abi_info` remains byte-for-byte unchanged. |
| `bg2_create_projection_query_set` | `(patch_handle, slots, count, targets, target_doubles, seeds, seed_doubles, out_handle, diag, diag_bytes)`; exact `3*count` target and `2*count` seed extents; creator output starts zero. |
| `bg2_project` | `(projection_query_handle, options, options_bytes, out_handle, diag, diag_bytes)`; copy/validate one fixed-width options descriptor, allocate a distinct result, synchronize before publication. |
| `bg2_projection_info` | `(projection_result_handle, info, info_bytes, diag, diag_bytes)`; count, patch count, backend, profiling flag/elapsed kernel time and field count. |
| `bg2_projection_download` | `(result_handle, fields, field_doubles, statuses, status_count, iterations, iteration_count, evalcounts, evalcount_count, flags, flag_count, diag, diag_bytes)`; all extents exact and every output pair checked for overlap before writing. |
| `bg2_projection_sources` | `(result_handle, patches, patch_count, patch_bytes, slots, count, targets, target_doubles, seeds, seed_doubles, options, options_bytes, diag, diag_bytes)`; copies retained host provenance with exact payload extents and a versioned options destination. |
| `bg1_close` | Recognizes the two new kinds in the same registry. Existing stale-handle and context-close semantics apply. Existing evaluator info/download functions reject these new result kinds. |

No query/result handle is accepted by the other operation's entry points. Prefixes do not establish handle type: the registry checks it. A new core supports old evaluator callers and v1-only plugins. An old core remains a valid evaluator core but lacks `bg2_*` symbols; the new Python adapter must detect that lazily when projection is requested and raise explicit unsupported. Ordinary evaluator use of that adapter should still work.

Proposed new info layout is 48 bytes on the existing Linux x86-64 contract: two u32 version/size fields; two u64 counts; four u32 backend/flags/field-count/reserved fields; one double kernel time. Options require exact version/size, zero reserved/unknown flags, bounded maximum-iteration/backtracking counts and a finite bounded projected-gradient tolerance. Check worst-case evaluation-count arithmetic against the u32 output bound before launch; profiling remains a context timing choice, not a convergence option. A proposed 32-byte options record is `u32 abi_version, struct_size, max_iterations, max_backtracks; double gradient_tolerance; u32 flags, reserved`. Numerical recommendations currently use tolerance `2^-24`, 64 accepted updates (supported option range 1..256), 24 trial halvings, and an internal infinity-norm step cap of 0.25. The numerical design must finalize the backtracking/tolerance admissible ranges, whether a backtracking count includes the initial full trial, evaluator-call accounting and stopping logic before headers are implemented. A small step or small objective change alone is never stationary success. Caller byte capacity may exceed a canonical descriptor, but `struct_size` must equal the supported structure. Numeric payload extents are exact, consistently with the existing API.

Request arrays use the existing borrowing convention: slots are native aligned u32, targets are native aligned FP64 triples `[x0,y0,z0,...]`, seeds are FP64 pairs `[s0,t0,...]`. The core first copies into owned vectors, then validates and uploads those same snapshots. Overflow checks cover each width/count multiplication, size_t conversion and container limit. Empty batches accept null payloads and publish valid empty query/result objects without kernel launches. They still validate descriptors/options and handle kinds.

A valid query row can contain an invalid slot, nonfinite target, nonfinite/out-of-range seed, or target outside the supported numerical envelope. These are per-request outcomes at projection, not upload-time whole-batch exceptions. Structural shape/type/alignment failures remain batch errors. The emerging numerical recommendation admits finite local targets with each absolute coordinate at most 4 and seeds in closed `[0,1]`, with no silent clamping or reseeding. Specify deterministic error precedence once in the numerical contract so CPU and CUDA classify identical inputs.

## Compact output and numerical status boundary

The integrated output proposal is seven FP64 planes with full batch stride: `fields[field*count+i]` in order `(s,t,x,y,z,distance_squared,projected_gradient_residual)`, plus four u32 slabs: status, iteration count, evaluator-call count and diagnostic flags. That is 72 bytes per request, compared with 144 floating bytes for order-2 evaluator jets before its status array. Device iteration consumes order-2 jets internally; no per-iteration host transfer or retained derivative history is needed. Diagnostic flags record rank/curvature classification without changing a stationary candidate into a minimum/global claim.

Use the numerical unit's proposed raw box residual `||x - P_[0,1]^2(x-g)||_infinity`, with `x=(s,t)` and `g=J^T(S-Q)` for the local objective `0.5*||S-Q||^2`. The projection onto the unit square is componentwise. This residual uses normalized parameters and the local objective; it is not a spatial-distance error estimate. Ordinary interior orthogonality and this projected-gradient residual differ at boundaries. No Hessian-based normalization may hide tiny charts. Its infinity norm is at most one for an admitted box point; the numerical unit must state exact rounding/convergence acceptance, not infer geometric quality from that bound.

Preserve a finite best accepted candidate for iteration-limit, line-search-limit, stagnation and unresolved curvature/rank outcomes when evaluation remains valid. Its mandatory status and flags prevent `require_stationary()` from accepting an unresolved outcome. Invalid slot/target/seed and evaluation arithmetic failure instead have all seven numeric fields NaN. Report the residual recomputed at the exact reported UV, not a previous/trial iterate. Classification flags separately distinguish interior/boundary, rank, negative curvature and ambiguity; a flag cannot silently change the status meaning. The status domain distinguishes stationary, unresolved/negative-curvature/degenerate, iteration limit, line-search limit, stagnation, invalid input and arithmetic outcomes; exact numbering and precedence remain canonical-header decisions after design review. A stationary status does not certify a local minimum. Preserve row ordering and specify iteration/evaluator-call conventions for validation rejection, zero-step stationarity and termination exactly once in the numerical design. Do not alter the existing evaluator status or NaN rule.

All success and unresolved candidates remain local-patch objects. The source UV conversion is affine only within the stored patch rectangle; world position/distance conversion uses the stored origin and scale with an explicit supported envelope. Metadata conversion is a host consumer operation and does not prove trim membership or global distance. Projection must neither call `bg1_convert` on its unrelated seven-field result layout nor silently interpret local targets as world coordinates.

## Private v2 extension and old-plugin behavior

Keep exporting `brepgpu_cuda_backend_v1(requested=1, out_v1, diag)` unchanged. Add `brepgpu_cuda_backend_v2(requested=2, out_v2, diag)` in the same optional plugin. The new core first loads/validates the existing v1 table exactly as today. It requests v2 only for a projection capability query or operation; failed extension discovery must not disable that context's evaluator functionality.

Proposed `bg_backend_v2` starts with u32 version/size, u64 capabilities, and `const bg_backend_v1* base`. Require exact v2 layout/capability checks and `v2->base == plugin->table`. The new plugin's v2 table references the same stable static v1 table returned by its v1 factory. This is an explicit compatibility promise for opaque tokens, not a guess that two unrelated tables happen to share callback names.

The extension adds only these callbacks, returning existing status/diagnostic records:

```text
projection_query_create(ctx_token, patch_token, slots, count,
                        targets_xyz, seeds_st, out_query_token, diag)
projection_query_close(ctx_token, query_token, diag)
project(ctx_token, query_token, options, out_result_token, profile, diag)
projection_result_close(ctx_token, result_token, diag)
projection_download(ctx_token, result_token, fields, field_doubles,
                    statuses, status_count, iterations, iteration_count,
                    evalcounts, evalcount_count, flags, flag_count, diag)
```

Do not pass a projection token to any v1 query/evaluate/result callback. The plugin extension owns its private token structures, which refer to the same private context/patch objects. Existing v1 callbacks remain valid on their original token kinds. The core remains the sole public handle registry and process poison authority. Projection provenance/options are retained in owned host snapshots by the core; no plugin callback is needed to export source identity.

A v1-only plugin returns `BG_UNSUPPORTED` for a requested projection operation before creating any projection allocation. A present malformed v2 table or incompatible base identity also returns an explicit projection capability error, preserving evaluation. Missing CUDA module/runtime still produces the existing backend-unavailable error at CUDA context creation. None of these cases falls back to CPU. Do not load a second plugin, independently initialize another CUDA runtime, create a second context for the same public handle, or reinterpret v1 token storage to acquire the extension.

## Ownership, synchronization and failure behavior

Extend the current ownership graph: projection result retains projection query; projection query retains patch set; each retains the same context and plugin. The context tracks public IDs without strongly retaining children. Patch/query public close revokes those IDs while private dependencies remain usable; a live result's downloaded provenance survives both closes. Context close invalidates every public child kind and waits for an admitted operation under the context lock. Promoted calls waiting for that lock must recheck context OPEN and public handle identity before accessing payload or launching.

Use the existing registry promotion/context lock ordering and existing process-wide fatal/publication serialization. Add new objects to the existing native child-token count only after successful private creation. Cleanup calls the correct extension callback once; the v1 context token is closed only after all evaluator and projection tokens drain. Retain the plugin/v2 table through this cleanup. Use the existing unpublished-publication cleanup helper so OOM plus fatal cleanup preserves primary error identity, adds fatal flags/cause and publishes no handle.

Every CUDA callback saves the calling thread's device, selects the context device, uses its existing stream, completes owned work and restores the prior device before publishing success. Device selection belongs to the host thread; CUDA's documented device/stream ownership supports retaining this per-entry discipline. The implementation remains CUDA 12/P100; consulting the current device API here does not expand hardware support. [NVIDIA device API](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__DEVICE.html). Explicit stream completion reports queued failures; stream destruction by itself is not the public completion contract. [CUDA 12.8 stream API](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-runtime-api/group__CUDART__STREAM.html).

Each `project` allocates a distinct result while resident patch/query inputs can be reused. A nonfatal creation/launch/completion/restoration failure returns a batch error and zero result handle. Unsupported convergence/input conditions belong to per-row statuses, not `bg_status`. A failed download after preflight can partially write any destination; callers discard all five arrays, while Python publishes none. Preflight-rejected downloads write no payloads. Fatal callback or cleanup errors poison the common CUDA backend, invalidating evaluator and projection operations/results in all contexts; CPU remains usable. There is no automatic reset, retry or device migration.

## Python boundary

Keep the owned standard-library adapter. Add `Engine.create_projection_query_set(patches, patch_slots, targets, seeds)`, `Engine.project(queries, options)`, projection query/result resource wrappers, and an owned downloaded `ProjectionBatch` with candidate/status/iterations/evaluator-count/flags/residual accessors and `require_stationary()`. All resource wrappers retain the engine, use native close and support context managers. A downloaded batch retains the core library and copied provenance but needs no live native resource.

Declare projection symbols lazily and verify the extension's ABI-info layout before projection use; do not make module import or evaluator-only engine creation require them. Pack private aligned arrays and an owned options copy before a `ctypes.CDLL` call. Retain exporters through the call and publish new host arrays only after native success. Caller mutation while packing remains outside the snapshot construction contract; mutation after native admission does not change the copied query. CPython's foreign-library calls release the GIL, so shared user buffers cannot serve as the stable upload image. [Python 3.12 ctypes](https://docs.python.org/3.12/library/ctypes.html).

No borrowed device-pointer exposure, Python callbacks, asynchronous handles, native-buffer aliasing or binding library is needed for this delivery. Reference scalar/global-projection timing is labeled separately from this owned seeded batch and cannot substitute for the owned CPU baseline.

## Required comparisons and accounting

Run the same native operation, inputs, convergence settings and direct numerical checks on CPU one worker, CPU 24 workers, P100 device 0 and P100 device 1. GPU timings use each card separately; do not claim a two-card dispatch speedup. Use full batch stride and disjoint ranges for CPU workers, preserving join-on-partial-thread-start cleanup. Start with counts 32, 256, 4096, 65536 and 1048576, adjusted only with recorded reasons. Group easy/already-converged, short refinement, difficult/stalled and invalid requests; iteration divergence and failure distributions affect the operation's cost.

| Timing scope | Included work |
| --- | --- |
| Resident project | Existing public patch/query handles; options validation/copy, distinct result allocation, refinement, stream completion/restoration, public publication. No download. Native wall time is the main measure. |
| Resident project plus compact host output | Resident scope plus exact-size host result allocation, all output downloads and required result/status checking. Show allocation, transfer and validation where measured separately. |
| Cold host task | Patch snapshot/validation/upload, target/seed packing and query upload, project, compact download, provenance/frame conversion and required checks. Report context/module warm-up and source extraction separately as well as their complete-task inclusion when relevant. |
| Optional kernel diagnostic | Profile events on the owned stream, reported separately from default-profile-off wall-time rows. Not a substitute for allocation/completion/transfer costs. |

Use distinct result allocations consistently on CPU and GPU; do not benchmark reusable private GPU output storage against allocating public CPU results. Close results outside the stated resident interval but measure/report cleanup separately. Do not evade whole-task transfer cost by comparing GPU resident input with CPU Python scalar calls. Separate Python packing/FFI overhead from the native comparison and record it for the public Python task. Report batch size, patch-family mix, valid/converged/unresolved/invalid counts, iteration distribution, residual/outcome summaries, H2D/D2H bytes, retention and retry/fallback counts/time. This operation has no implicit fallback; if a consumer explicitly falls back, its time and unresolved outputs belong to that consumer's task row.

Raw input storage is 44 bytes per row (u32 slot, three FP64 targets, two FP64 seeds); compact result storage is 72 bytes per row. Host provenance and device input are both retained for GPU queries. Patch storage, allocator overhead, context state, temporary solver/event storage and downloaded host output add to those figures. Record measured RSS/device memory alongside these structural sizes, including objects retained after public parent close. No projection speedup is measured by this study; the existing evaluator results do not establish it.

## Decisions required before implementation

1. Finalize the numerical box-stationarity operation and boundary behavior. Give every outcome/status, curvature/rank flag, candidate-validity rule, projected-gradient residual, iteration/evaluator-call count and acceptance convention an exact definition. The accepted direction returns local stationary or unresolved candidates without a minimum/global promise.
2. Finalize the proposed local target envelope `|coordinate|<=4`, closed normalized seed policy, deterministic invalid-row precedence and bounded options with numerical units. Preserve the existing patch/control support envelope unless separately reviewed.
3. Accept the additive public extension/version and lazy v2 table bound to the original v1 table; define capability error behavior for v1-only, malformed-v2 and old-core cases.
4. Accept distinct immutable projection resources and fresh result allocation, with the same common fatal state and cleanup graph. Define the compact field order and exact shapes once in canonical headers after plan acceptance.
5. Select direct analytic/model fixtures and unresolved cases independently of CPU parity. Runtime tests should attack actual new kinds, provenance snapshots, old-plugin compatibility and fault/admission/publication boundaries; reuse existing direct lifetime mechanisms where they attack the same invariant.

Useful runtime attacks are old-core evaluator use by the new adapter, v1-only plugin evaluation plus projection refusal, malformed-v2/base-mismatch refusal before allocation, foreign/wrong-kind/stale projection handles, immutable target/seed/options snapshots, empty shapes, exact download extents/alignment/overlap, result provenance after parent close, per-thread device restoration and cross-operation fatal poison. Extend the owned fault model at the real projection creation/publication/download/cleanup boundaries; do not claim modeled callbacks induce hardware failure.
