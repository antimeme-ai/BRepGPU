F=3,584,C=15,360; 32,768 instances give E=491,520,F=229,376,C=983,040. These fit

The 65,537-edge direct case creates 257 scan blocks at 256 lanes, requiring
block-total recursion beyond a single totals block. Make its coedge distribution
uneven with nonzero uses on both sides of scan boundaries, plus empty interior
and tail rows; all-empty offsets alone would not attack uniform-add correctness.
The independent relation model compares row multiplicities and per-coedge
mate/neighbor identities without imposing row order. High-degree, same-sign,
same-face, empty and mixed/repeated-instance inputs attack different semantic
classes and stay labelled as incidence graphs when not geometric B-reps.

Implementation details to preserve from the accepted plan:

- Decode actual owned output bytes independently with exact extents. Do not
  use product result accessors to certify membership/provenance.
- Keep canonical source projection truth distinct from the generic dictionary
  incidence model; a consistently wrong flattening must not pass by agreement.
- Test permutations through full typed occurrence keys, including body,
  revision and instance, rather than current dense numeric entity order.
- Native malformed-call tests reach structural/content admission and assert
  unchanged payload destinations; unsupported oversized counts are rejected
  before array reads and do not certify execution of enormous prefixes.
- Actual CUDA builder and reader mutant kills require healthy baseline and
  independent assertion failure on real device output. Build/import failures
  do not count. Host sanitizer and device memory tests are separate fault
  mechanisms; no aggregate universal correctness claim is implied.
- Fleet execution is root-serialized, protecting measured trials from builds,
  copying, qualification or mutation work. Old numerical libraries stay intact.

The oracle and tests remain one conceptual ownership unit. Native admission
and runtime fault tests belong to the native owner; no parallel owner splits
that resource-lifetime invariant. No new dependencies or integration tuning
are necessary. No product edits or tests were made during this review.
